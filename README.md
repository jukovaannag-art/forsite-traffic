# Пробки Иркутска - сбор и дашборд (проект Форсайт)

Раз в час с 7:00 до 23:00 по Иркутску снимается балл пробок из двух источников и
складывается в один CSV. Сборщик опрашивает источники каждые 10 минут, в файл
попадает первый удачный замер часа. Дашборд показывает среднее за день, профиль
по часам и тепловую карту день x час - за неделю, две, месяц, всё время или за
любые свои даты («Свой период» в фильтре открывает календарь).

## Что откуда берётся

| Источник | Эндпоинт | Что отдаёт |
|---|---|---|
| Яндекс.Пробки | `export.yandex.ru/bar/reginfo.xml?region=63` | балл 0-10, текст («Местами затруднения»), суммарная длина пробок |
| 2ГИС | `jam.api.2gis.com/scores?view=<bbox Иркутска>&z=11` | балл 0-10 по проекту `irkutsk` |

Оба публичные, ключей не требуют. Это тот же эндпоинт, который дёргает сам
`2gis.ru/irkutsk?traffic`, и тот, что питает виджет пробок Яндекса.

**Баллы двух источников не смешиваются в одно число.** Методики разные: на одном
и том же часе Яндекс может показать 3, а 2ГИС - 1. Сравнивать их можно только
рядом друг с другом и в динамике, среднее «по обоим» смысла не имеет.

## Как это работает

```
collect.py            -> опрашивает источники, дописывает строку в CSV
collector/sources.py  -> провайдеры (yandex, 2gis)
collector/storage.py  -> запись в CSV, дедупликация по (дата, час, источник)
data/traffic_irkutsk.csv -> вся история, одна строка = один источник за один час
dashboard/app.py      -> Streamlit-дашборд поверх этого CSV
collector/health.py   -> проверка здоровья сбора (молчит ли, отвечают ли источники)
watch.py              -> сторож: собирает письмо о статусе и шлёт на почту
worker/traffic-worker.js -> тот же сбор на Cloudflare Workers, главный планировщик
.github/workflows/collect.yml -> долгий прогон в облаке: опрос по кругу и коммит новых строк
.github/workflows/watch.yml   -> сторож по расписанию, письма на почту
```

Сбор идёт в облаке, компьютер включать не нужно. Планировщиков два, и это
намеренно: **главный - Cloudflare Workers**, GitHub Actions остался запасным.
Оба пишут в один файл и не мешают друг другу - час, закрытый одним, второй не
трогает (`upsert` по дате, часу и источнику). В истории их видно по подписи:
`traffic-worker` против `traffic-bot`.

Почему главный не GitHub. Расписание Actions сначала редело (исполнялось около
16% тиков), а 26-28.08.2026 замолчало совсем: 59 часов без единого запуска по
cron при полутора сотнях ожидаемых, без баннера и без письма. Ручной запуск при
этом стартовал мгновенно - то есть отказало именно расписание. Похоже, его
задушил наш же долгий прогон: задание, занимающее раннер по 5.5 часов почти
круглосуточно, GitHub перестаёт будить. Проверять это надо не глазами по
странице Actions, а запросом
`api.github.com/repos/jukovaannag-art/forsite-traffic/actions/runs?event=schedule` -
там видно время запусков и отменённые, которых в вебе не видно.

**Расписание тут - не «когда снимать балл», а «когда попытаться поднять
сборщик».** Замерено 18-26.08.2026: GitHub исполняет примерно 16% тиков
расписания (8 запусков в сутки из 51 заявленного) и опаздывает на 5-60 минут.
Учащение тиков не лечит - переход с одного раза в час на три дал +1 замер в
сутки. Поэтому прогон, которому повезло стартовать, не снимает один балл и не
уходит: он остаётся в эфире до 5.5 часов (потолок задания у GitHub - 6) и
опрашивает источники каждые 10 минут сам. Одного удачного старта хватает на
треть суток, а `concurrency` ставит следующий прогон в очередь - он подхватит
эстафету, когда у текущего кончится бюджет.

Ночью прогон не опрашивает источники, но и не выходит: старт, случившийся до
7:00, - уже выигранный билет, разбрасываться им нельзя. Он досыпает до открытия
окна и начинает собирать ровно в 7:00. Поэтому в расписании есть предутренние
часы (20-23 UTC = 4:00-7:59 местного) и нет глухой ночи: квота исполненных тиков
у GitHub общая на сутки, и тик, потраченный в два часа ночи, отнимается у утра.

Внутри часа засчитывается первый удачный замер, остальные пять опросов -
бесплатные ретраи: `upsert` схлопывает их по (дата, час, источник), файл не
меняется, коммита нет. Если час закрылся ошибкой источника, следующий опрос
через 10 минут заменит строку с ошибкой на удачную.

Минуты Actions на публичном репозитории не тарифицируются - длинный прогон
ничего не стоит.

## Сборщик на Cloudflare Workers

`worker/traffic-worker.js` - один самодостаточный файл, сборка не нужна. Он
делает то же, что `collect.py`, но живёт на чужом планировщике: опрашивает
источники, читает CSV через GitHub Contents API, сливает по тем же правилам и
пишет обратно.

Через терминал:

```bash
npx wrangler login                                    # один раз, откроет браузер
npx wrangler deploy -c worker/wrangler.toml
npx wrangler secret put GITHUB_TOKEN -c worker/wrangler.toml
```

Через браузер: Workers & Pages → Create → Start with Hello World → Deploy →
Edit code → вставить файл целиком → Deploy. Дальше Settings → Variables and
Secrets → Secret `GITHUB_TOKEN`, и Settings → Cron Triggers → `*/20 23,0-15 * * *`.

Токену нужны права **Contents: read/write** на этот репозиторий. Для заливки
файлов в `.github/workflows/` (сторож) дополнительно **Workflows: read/write** -
без него GitHub отвечает 403.

Проверить, что живой: открыть адрес воркера - он покажет, сколько часов закрыто
сегодня и когда последний замер, ничего не записывая. Ручной сбор по адресу
`/collect?key=...` работает, только если задан секрет `TRIGGER_KEY`; не задан -
писать снаружи нельзя вообще.

Тесты воркера (сеть не нужна):

```bash
node --test worker/tests.mjs
```

## Сторож: письма о статусе

`watch.py` + `.github/workflows/watch.yml` следят за самим сбором и пишут на
почту. Три прогона в сутки (11:00 и 17:00 - проверки, 23:30 - сводка за день по
местному времени), не чаще: квота исполненных тиков у GitHub общая на
репозиторий, и сторож не должен объедать сам сбор.

Что считается проблемой:

- **сбор молчит** - внутри окна 7:00-23:00 нет удачных замеров дольше двух
  часов. Ночью молчание законно, письма не будет;
- **источник сбоит** - три и более неудачных часа за сутки у Яндекса или 2ГИС.
  Один-два чинит следующий опрос, письмо тут лишнее. В письмо попадает текст
  последней ошибки, чтобы диагноз был сразу.

Утренняя и дневная проверки молчат, пока всё хорошо. Вечерняя пишет всегда -
она же и подтверждение, что сторож жив.

Доступы к почте лежат в секретах репозитория (Settings → Secrets and variables
→ Actions), в коде их нет:

| Секрет | Что это |
|---|---|
| `MAIL_USER` | ящик-отправитель целиком, вместе с доменом |
| `MAIL_PASSWORD` | пароль приложения почты, не обычный пароль от ящика |
| `MAIL_TO` | кому слать; если не задан, письмо уйдёт самому себе |

Почтовый сервер по умолчанию - Яндекс (`smtp.yandex.ru:465`). Пароль приложения
там выдают в Яндекс ID → Безопасность → Пароли приложений → Почта, и в
настройках почты должен быть разрешён доступ по SMTP. У Google пароли приложений
доступны только при включённой двухэтапной аутентификации - поэтому не он.
Другой сервер задаётся переменными репозитория (не секретами) `MAIL_HOST` и
`MAIL_PORT`: для Gmail это `smtp.gmail.com` и `465`.

Посмотреть письмо, ничего не отправляя:

```bash
python watch.py --mode daily --dry-run
```

## Локально

```bash
python collect.py                # снять балл прямо сейчас
pip install -r requirements.txt  # для дашборда
streamlit run dashboard/app.py
```

Сборщику зависимости не нужны - только стандартная библиотека Python 3.10+.
`requirements.txt` нужен лишь дашборду.

## Формат данных

`data/traffic_irkutsk.csv`, колонки:

- `ts_utc`, `ts_local` - момент замера (локальное время - иркутское)
- `date`, `hour` - локальные дата и час, по ним считаются средние
- `source` - `yandex` или `2gis`
- `score` - балл 0-10; **пусто, если источник не ответил**
- `hint` - словесная расшифровка (только Яндекс)
- `jams_length` - суммарная длина пробок по версии Яндекса
- `error` - причина пропуска

Строки с пустым `score` остаются в файле намеренно: пропуск должен быть виден,
а не выглядеть как «пробок не было».

## Что помнить про данные

- **Дырки бывают.** Дыра теперь стоит не одного часа, а целого прогона: пока
  сборщик в эфире, он закрывает часы сам, но если очередной старт не случился
  до конца бюджета предыдущего, пропадает весь промежуток. Плитка «Полнота сбора»
  на дашборде показывает, какая доля из 17 замеров в день реально собрана; при
  низкой полноте среднее за день считать осторожно. Первый и последний день
  периода в знаменателе считаются от фактического замера, а не от 7:00 и 23:00.
- **Замер может сползти за полночь.** Сильно опоздавший запуск запишется часом
  0-6. Сборщик пишет такие строки намеренно - терять отработавший прогон хуже;
  из средних дашборд их исключает и показывает счётчик отдельной подписью.
- **История не восстанавливается задним числом.** Оба источника отдают только
  «прямо сейчас». Пропущенный час пропущен навсегда.
- **Балл - это оценка города целиком**, а не конкретного маршрута. Для вопросов
  вида «сколько ехать до Первомайского в 18:00» он не годится.

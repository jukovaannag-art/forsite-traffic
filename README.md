# Пробки Иркутска - сбор и дашборд (проект Форсайт)

Раз в час с 7:00 до 23:00 по Иркутску снимается балл пробок из двух источников и
складывается в один CSV. Сборщик пробует каждые 20 минут, в файл попадает первый
удачный замер часа. Дашборд показывает среднее за день, профиль по часам и
неделю целиком.

## Что откуда берётся

| Источник | Эндпоинт | Что отдаёт |
|---|---|---|
| Яндекс.Пробки | `export.yandex.ru/bar/reginfo.xml?region=63` | балл 0-10, текст («Местами затруднения»), суммарная длина пробок |
| 2ГИС | `jam.api.2gis.com/scores?view=<bbox Иркутска>&z=11` | балл 0-10 по проекту `irkutsk` |

Оба публичные, ключей не требуют. Это тот же эндпоинт, который дёргает сам
`2gis.ru/irkutsk?traffic`, и тот, что питает виджет пробок Яндекса.

**Баллы двух источников не смешиваются в одно число.** Методики разные: на одном
и том же часе Яндекс может показать 3, а 2ГИС - 1. Сравнивать их можно только
рядом друг с другом и в динамике, среднее «по обоим» смысла не имеет.

## Как это работает

```
collect.py            -> опрашивает источники, дописывает строку в CSV
collector/sources.py  -> провайдеры (yandex, 2gis)
collector/storage.py  -> запись в CSV, дедупликация по (дата, час, источник)
data/traffic_irkutsk.csv -> вся история, одна строка = один источник за один час
dashboard/app.py      -> Streamlit-дашборд поверх этого CSV
.github/workflows/collect.yml -> запуск в облаке каждые 20 минут и коммит новых строк
```

Сбор идёт в GitHub Actions по расписанию `*/20 0-15,23 * * *` (UTC). Иркутск -
UTC+8 круглый год, поэтому это ровно 7:00-23:00 по местному времени. Компьютер
для сбора включать не нужно.

Попыток три на час, а не одна: GitHub выбрасывает часть запусков по расписанию
молча, и раньше один пропуск стоил целого часа. Второй и третий прогон внутри
часа ничего не пишут - `upsert` схлопывает их по (дата, час, источник).

## Локально

```bash
python collect.py                # снять балл прямо сейчас
pip install -r requirements.txt  # для дашборда
streamlit run dashboard/app.py
```

Сборщику зависимости не нужны - только стандартная библиотека Python 3.10+.
`requirements.txt` нужен лишь дашборду.

## Формат данных

`data/traffic_irkutsk.csv`, колонки:

- `ts_utc`, `ts_local` - момент замера (локальное время - иркутское)
- `date`, `hour` - локальные дата и час, по ним считаются средние
- `source` - `yandex` или `2gis`
- `score` - балл 0-10; **пусто, если источник не ответил**
- `hint` - словесная расшифровка (только Яндекс)
- `jams_length` - суммарная длина пробок по версии Яндекса
- `error` - причина пропуска

Строки с пустым `score` остаются в файле намеренно: пропуск должен быть виден,
а не выглядеть как «пробок не было».

## Что помнить про данные

- **Дырки бывают.** GitHub Actions по расписанию задерживается на 5-60 минут и
  часть запусков выбрасывает совсем - это нормальное поведение бесплатных
  раннеров, ретрая для пропущенного тика не существует. Плитка «Полнота сбора»
  на дашборде показывает, какая доля из 17 замеров в день реально собрана; при
  низкой полноте среднее за день считать осторожно. Первый и последний день
  периода в знаменателе считаются от фактического замера, а не от 7:00 и 23:00.
- **Замер может сползти за полночь.** Сильно опоздавший запуск запишется часом
  0-6. Сборщик пишет такие строки намеренно - терять отработавший прогон хуже;
  из средних дашборд их исключает и показывает счётчик отдельной подписью.
- **История не восстанавливается задним числом.** Оба источника отдают только
  «прямо сейчас». Пропущенный час пропущен навсегда.
- **Балл - это оценка города целиком**, а не конкретного маршрута. Для вопросов
  вида «сколько ехать до Первомайского в 18:00» он не годится.
